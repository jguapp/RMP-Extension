Anatomy of an Extension

Every file in this repository, what it does, and why it exists — plus the concepts underneath them. The extension is about 3,500 lines of plain JavaScript with no framework, no bundler, and no build step, which makes it unusually good to learn from: what you read is what runs.

The mental model

Three worlds that cannot touch each other

The single most important thing to understand about browser extensions is that they are not one program. They are three programs that run in different places, with different powers, and can only talk by passing messages.

Content script

Runs inside the CUNYfirst page Can touch the page's DOM. Cannot fetch from other websites.

↕ chrome.runtime.sendMessage

Background

Runs on its own, with no page Can fetch from ratemyprofessors.com. Cannot see the page at all.

↕ chrome.runtime.sendMessage

Popup

A tiny web page that opens under the toolbar icon Exists only while open. Dies the moment you click away.

Concept · The isolated world

A content script shares the page's DOM but not its JavaScript. If CUNYfirst defines window.foo, your content script can't see it, and vice versa. This is a security boundary, and it's why nothing the page does can reach into the extension.

It also means the extension's variables are invisible to the page. That is why every file here hangs its exports off one global called RMPX — inside the isolated world, that global is private.

Concept · Why the split exists at all

Content scripts are deliberately forbidden from making cross-origin requests. If they weren't, any extension could silently read your bank from a page you had open. So the content script finds a professor's name, hands it to the background, and the background — which has no access to the page — does the network call. Neither half has enough power on its own to be dangerous.

The journey of one name

End to end, in nine steps

Everything in this codebase serves one path. Follow Smith,John A from pixels on a page to a rating badge:

  1. Find it. scanner.js walks the DOM looking for text that could be an instructor name.
  2. Parse it. name-utils.js turns "Smith,John A" into { first: "John", last: "Smith" }.
  3. Wrap it. badge.js splits the text node, wraps the name in a link, and drops a loading badge beside it.
  4. Ask. content.js messages the background with the parsed name, the campus, and a department hint.
  5. Check the cache. cache.js answers instantly if this professor was looked up recently.
  6. Search. rmp-client.js queries Rate My Professors' GraphQL API.
  7. Choose. matching.js scores every candidate and rejects anything below the bar — a wrong rating is worse than none.
  8. Paint. The result travels back and badge.js fills in the score and colour.
  9. Hover. hovercard.js fetches the full breakdown on demand and draws the preview card.

Foundation

The file every other file depends on

src/lib/namespace.js 149 lines

Shared constants, defaults, and the RMPX global.

Loaded first, everywhere. It holds the version, the list of files that make up the content-script and background bundles, the message-type names, cache lifetimes, and small pure helpers like professorUrl() and ratingTone() (which maps a score to green / yellow / red).

The file lists matter more than they look. The manifest, the background's importScripts call, and the dynamic site registration all need the same list in the same order, and a test asserts they never drift apart.

Concept · The classic-script pattern

Every file here is wrapped the same way: 

(function (root) {
  'use strict';
  const RMPX = (root.RMPX = root.RMPX || {});
  // ...
  RMPX.thing = { ... };
  if (typeof module !== 'undefined' && module.exports) module.exports = RMPX.thing;
})(typeof self !== 'undefined' ? self : globalThis);

That last line is the trick. The same file can be loaded as a content script (self is the window), inside a service worker (self is the worker), or require()d by Node in the tests. One source, three runtimes, no build step — which is why the unit tests can run with zero dependencies.

Reading the page

Finding names in markup you do not control

This is the hardest part of the whole extension, and the reason is structural: CUNY runs at least two entirely different systems, and each campus skins them differently. There is no reliable CSS selector.

src/content/scanner.js 378 lines

Finds candidate instructor names in the DOM.

Rather than betting on one selector, it runs four independent strategies and unions the results:

  • The element is marked as an instructor (class="instructor", PeopleSoft ids, and so on).
  • The marker is an icon, and the name is the sibling next to it — Schedule Builder renders rows as icon + text, where the only thing carrying the word "Instructor" is a tooltip.
  • The column under a table header that says Instructor.
  • Text following an Instructor: label.

Everything it returns is a text node, not an element. That is deliberate, and the next file explains why.

src/lib/name-utils.js 483 lines

Turns messy roster strings into structured names.

The largest library file, because real data is filthy. It handles "Smith,John A", "SMITH, JOHN", "Dr. John Smith, Ph.D.", "Smith,John; Doe,Jane", and knows that Staff, TBA and To be Announced are not people.

It also strips honorifics and credentials, folds surname particles (van der) into the surname, and carries a nickname table so Bob Smith on the roster matches Robert Smith on RMP.

Two guards do the heavy lifting: PLACEHOLDERS (values meaning "nobody assigned") and NON_NAME_WORDS (words that appear in the Title Case phrases sitting right next to instructor names — Baruch College, Online Synchronous). Both are deliberately conservative: anything that is also a plausible surname — Hall, Church, Park, Young — is left out on purpose.

src/lib/subjects.js 99 lines

Maps a course code to a department name.

ACC 3202 → Accounting. This becomes a hint passed to the matcher: if two professors share a name and one teaches Accounting, the course code breaks the tie.

Concept · Text nodes vs elements

In the DOM, <td>Smith,John A</td> is an element containing a text node. Most code works with elements, but this extension works with text nodes, because a cell can hold two instructors separated by a semicolon and each needs its own link.

splitText(offset) cuts one text node into two at a character position. Splitting twice isolates exactly one name in its own node, which can then be moved inside a link — without ever rebuilding the host page's markup.

Drawing on the page

Adding UI to a page you are a guest in

src/content/badge.js 235 lines

Injects the link and the rating badge.

The guiding constraint is to disturb the host application as little as possible. It never rebuilds markup with innerHTML and never discards the original text node — the node is split and re-parented inside an anchor, so any reference CUNYfirst's own JavaScript holds to that node still points at something real.

Every injected element carries a data-rmpx attribute. That is how the scanner recognises its own output and skips it on the next pass, and how removeAll() can restore the page exactly — a test asserts the page comes back byte for byte.

Security · Why never innerHTML

Instructor names come from a web page, which means they are untrusted input. Writing untrusted text with innerHTML would let a crafted name inject script. Using textContent makes that structurally impossible — the browser treats the value as text, always. A test scans the whole source tree and fails if innerHTML ever appears.

src/content/hovercard.js 454 lines

The hover preview card.

Rate My Professors sends an X-Frame-Options header, so you cannot simply put their page in an iframe. The card is therefore rebuilt natively from the same data: headline score, difficulty, would-take-again, the Awesome / Good / Bad split, the 5-to-1 histogram, and the tags.

One card instance is reused for the whole page. It opens on hover and on keyboard focus, and stays open while the pointer is inside it so the links remain clickable. Detail is fetched only when you hover — 40 instructors on a page would otherwise mean 40 extra requests nobody asked for.

Concept · Race conditions in UI

Hovering fires an async fetch. Move to another name before it returns and the first response would paint into the wrong card. The fix is a token: each open increments detailRequestToken, and when the fetch resolves it checks whether its token is still current. If not, it throws the result away. This pattern appears anywhere async work races user input.

src/content/styles.css 447 lines

Every injected style, namespaced.

These rules land inside pages carrying aggressive global CSS, so every selector is namespaced under .rmpx-* and qualified with [data-rmpx] to raise specificity. Properties that matter for legibility are stated explicitly rather than inherited, because the host page's font-size cannot be trusted.

Colours come from CUNY's official identity palette as custom properties, with a full dark-mode block. Rating tones stay semantic — green reads as good regardless of brand — but each is drawn from CUNY's own accents.

src/content/content.js 344 lines

The orchestrator: campus detection, scanning, lifecycle.

Detects which campus the page belongs to by trying five signals in order (institution dropdown, page title, header branding, URL, body text), drives the scan, sends the lookups, and owns the MutationObserver that notices when Schedule Builder loads new results.

Concept · Debouncing a MutationObserver

A MutationObserver fires on every DOM change — potentially hundreds per second while a results table renders. Rescanning on each would be catastrophic. So the observer only schedules a rescan, with a 350 ms debounce: repeated calls reset the timer, and the scan runs once the page goes quiet. It is then queued on requestIdleCallback so it never competes with rendering.

The background

The only code that talks to the network

src/background/service-worker.js 421 lines

Message handling, school resolution, the lookup pipeline.

Receives messages, owns the cache, and is the single choke point for outbound traffic. It also handles per-site opt-in: registering the content scripts on a Schedule Builder the manifest does not cover.

It runs in two different environments. Chrome loads it as a service worker, where dependencies must be pulled in at runtime with importScripts. Firefox and Safari load it as an event page, where importScripts does not exist and the manifest has already loaded those files — hence the guard around the call.

src/lib/rmp-client.js 380 lines

A thin client for RMP's GraphQL API.

This API is undocumented and unofficial, so every response is defensively unwrapped: any structural surprise degrades to "no data" rather than throwing into the page. RMP uses 0 and -1 as "no value" sentinels, which get normalised to null here so no badge ever reads "0.0 out of 5".

It is also a polite client. Requests are capped at 3 concurrent with a minimum gap between them, there is a 12-second timeout, and failures retry three times with exponential backoff — but only failures that might succeed on a retry. A GraphQL schema error is not retried, because it will fail identically forever.

Concept · GraphQL in one paragraph

A normal REST API gives you fixed endpoints returning fixed shapes. With GraphQL there is one endpoint, and you POST a query describing exactly the fields you want. Ask for a professor's name and rating and that is all you get back. It is efficient, but it means the server's schema can change underneath you — a field can quietly start returning nothing without any error at all. That is not hypothetical here; see §11.

src/lib/matching.js 194 lines

Decides which search result is actually the right person.

The most consequential file in the repo. RMP's search is fuzzy: query a surname and you get a dozen people. Each candidate is scored on surname, given name (including nicknames and bare initials), middle initial and department, and anything below MIN_ACCEPT_SCORE is discarded entirely.

When the top two candidates score within a hair of each other, the result is flagged ambiguous: the badge is marked and the hover card says so outright. The governing principle is that a wrong rating is worse than no rating — showing n/a is honest, showing the wrong professor is not.

src/lib/cache.js 184 lines

A TTL cache over chrome.storage.local.

Two goals: keep the page fast on repeat visits, and keep request volume against RMP low. Entries carry an expiry; hits live 7 days, misses 1 day (so a professor who has just joined RMP appears quickly), resolved school ids 90 days.

It keeps an in-memory mirror so one page render does not hammer storage, and prunes expired entries plus the oldest beyond a 1,500-entry budget.

Concept · In-flight de-duplication

A results page with 40 instructors may ask for the same professor several times at once. Cache lookups are async, so all of them would miss simultaneously and fire 40 requests.

The fix is to cache the promise, not just the result. The first caller starts the fetch and stores its promise in an inFlight map; everyone else gets handed the same promise. One network request, many awaiting callers. Note also that a thrown producer never reaches the cache — a network blip must not be stored as a permanent "no such professor".

src/lib/schools.js 270 lines

All 26 CUNY campuses, their aliases and codes.

Detection matches on word boundaries and prefers the longest alias, so Hunter College does not match inside another word and Borough of Manhattan Community College beats Manhattan. Campus keys are resolved to RMP's internal school id at runtime and cached for 90 days.

src/lib/origins.js 63 lines

Which sites may be injected into — and which never may.

Sorts an origin into three buckets: already covered by the manifest, the ratings API itself (never a page to annotate), or a legitimate opt-in. Small, but it exists because getting this wrong put badges all over Rate My Professors' own website. Being a plain module, its rules are unit-tested — including that cuny.edu.evil.com does not pass as CUNY.

The popup

Two controls, and deliberately only two

The extension is almost settings-free on purpose. Behaviour that has a right answer is simply the behaviour, not a preference. The popup carries only the two things that genuinely cannot be defaults.

FileLinesRole
popup.html52Structure: campus picker, site panel, disclaimer.
popup.css126Styling, with its own dark mode.
popup.js212Populates the campus list, saves changes, handles opt-in.

Campus exists because detection has to guess on pages that never name a college, and a wrong guess returns a real rating from the wrong school. This site exists because reaching a Schedule Builder the manifest doesn't cover needs a host permission, and browsers only grant those in response to a click.

Concept · Permissions that must be asked for

Extensions declare permissions up front, but broad ones can also be declared optional and requested at runtime. The catch: permissions.request() only works inside a user gesture. It must be called directly in a click handler — not after an await, which ends the gesture. That is why the permission prompt lives in the popup and the background only wires up the scripts afterwards.

Why three manifests

The extension source is identical on every browser. Only the manifest truly differs, so it is generated rather than kept as three files that drift:

ChromeFirefoxSafari
Backgroundservice workerevent pageevent page
Loads libraries viaimportScripts()manifestmanifest
Host permissionsat installat install (127+)per site, at use

Firefox has no service worker in Manifest V3 at all. A manifest declaring only service_worker installs happily there and then never runs any background code — the extension appears simply broken.

Concept · Writing a PNG without a library

make-icons.js is worth reading purely as an exercise. A PNG is a signature, then chunks: IHDR (dimensions), IDAT (pixels, zlib-compressed), IEND. Each chunk carries a CRC32 checksum. Node ships zlib, so the whole encoder is about 60 lines.

The letterforms are drawn as geometry — the C is a ring with a slot cut out of it, the U is two bars and a half-bowl — and sampled 6× per pixel for antialiasing. No font, no canvas, no dependency, and the icons can be regenerated on a bare checkout.

Those 119 tests use Node's built-in node:test and need no npm install at all. On top of them, dom.integration.js runs 29 checks by driving the real content scripts in headless Chromium against a fixture page, with the messaging layer stubbed so no network is involved. It asserts names are found, Staff rows are skipped, co-taught cells split into two links, the hover card renders the right numbers, and teardown restores the page exactly.

Concept · Tests can only catch what they can see

Both layers above are offline and deterministic, which is what makes them trustworthy — and also blind in one specific way. They cannot notice the third-party API changing shape. So there is a third layer, check:api, which hits the real endpoint weekly and asserts the response still looks the way the client expects. It is kept out of npm test deliberately: a third party being down should never fail somebody's pull request.

Concept · What the permissions actually buy

storage is the local cache. scripting registers content scripts on an opted-in site. activeTab reads the current tab's address when the popup opens — a narrow, gesture-scoped alternative to the far broader tabs permission.

The broad https://*/* entry is optional: no browser grants it at install. It exists solely so the "Turn on for this site" button has something to request, and each use grants exactly one origin.

Bugs that shaped the code

Five failures, and what each one left behind

Much of the defensive machinery above exists because of a specific failure. These are worth reading as a set, because each illustrates a different way software goes wrong.

1 · The feature that silently stopped existing

The hover card advertised "most common tags" and rendered none. RMP's teacherRatingTags field still answered — it just returned an empty list for every professor. Nothing threw. No test failed.

Fix: tally tags from the individual reviews instead, where they arrive as one ---separated string per rating. Lesson: a dependency can break without erroring, which is why check-api.js now exists.

2 · A person named "In Person"

On sections with no professor assigned, the extension linked In Person — the instruction mode — as though it were somebody's name. Two independent faults lined up: the stopword list held "inperson" as one word, but the checker split phrases on spaces first, so that entry was unreachable; and when a row said Staff, the scanner fell back to searching the row's parent, which in Schedule Builder contains every other row.

Lesson: a guard that cannot fire is worse than no guard, because it looks like coverage.

3 · Badges on Rate My Professors itself

permissions.getAll() returns the manifest's own host permissions alongside origins the user opted into. The re-registration loop treated them all alike, so it injected the content scripts into ratemyprofessors.com and badged their own listings.

Lesson: "everything I have permission for" and "everything I should act on" are different sets. That distinction is now origins.js, with tests.

4 · The constant nobody used

TTL.MISS_MS was defined, documented in two places as making misses expire sooner — and referenced nowhere. Every lookup, hit or miss, was cached for the full seven days, so a professor who had just joined RMP stayed invisible for a week.

Lesson: comments describe intent, not behaviour. Dead code is sometimes an unimplemented feature wearing a disguise.

5 · The number that looked bigger

The rating count appeared larger than the score despite identical font-size, font-weight and family. The cause was font-variant-numeric: tabular-nums, which forces every digit to a fixed advance width — 22% wider than the proportional digits beside it. Same height, wider glyphs, and the eye reads that as bigger.

Lesson: when the computed values say identical and your eye says otherwise, measure the rendered box.
